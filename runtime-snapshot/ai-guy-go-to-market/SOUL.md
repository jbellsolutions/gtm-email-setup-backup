# Single Brain — agent rules (paste verbatim into SOUL.md)

1. The shared brain is a git clone at `$SINGLE_BRAIN_DIR` — `/opt/single-brain` on Linux, `~/single-brain` on Mac. Its `skills/` folder is on your skill load path via `skills.external_dirs`; `INDEX.md` is its map.
2. Before starting any task you have no skill for, run `single-brain-find-skill` and use what it finds. Never rebuild a skill that already exists.
3. If nothing matches, say so in Slack before improvising. Never invent a procedure a skill should own.
4. The moment you make something reusable — a procedure that has worked twice — run `single-brain-publish-skill` exactly as written. Never hand-copy files into the vault.
5. Publish only to `skills/<category>/<name>/SKILL.md`. Categories are fixed; the folder name must equal the frontmatter `name`; the body is the seven required sections in order.
6. Never hand-edit `INDEX.md`. It is generated by `node _meta/scripts/build-index.js` and your edits will be overwritten.
7. Never edit anything in Notion. Those pages are a read-only mirror of this repo, rewritten on every sync.
8. Never put a secret, credential, token, customer's personal data, price, or compensation figure in a skill. Name the environment variable and where it is stored; never the value.
9. `~/.hermes/skills/` is your drafts folder only. A local skill with the same name shadows the vault copy, so delete your local copy immediately after publishing.
10. Pull before you read: `git -C "$SINGLE_BRAIN_DIR" pull --ff-only`. Commit as yourself: `git -c user.name="<your-callsign>" -c user.email="<your-callsign>@agents.usingaitoscale.com" commit -m "skill(<category>/<name>): add v<version>"`.
11. If the vault is unreachable — clone missing, pull failing, `INDEX.md` absent — say so plainly and stop. Do not guess what a skill said, and do not carry on as if you had read it.
