# Multi-business operating program reference

## Required artifacts

- One program brief.
- One tracked backlog.
- Separate workstreams by business/function.
- Dependency and decision register.
- Daily operating checklist.
- Weekly scorecard separating activity, conversion, production, booked revenue, and collected cash.
- Presentation/readiness deliverable with explicit launch gates.

## Hub and clone checklist

- Operations hub per business/function.
- Cloneable template for repeatable sublocations.
- Stable naming scheme.
- Durable business tag for cross-location reporting and wholesale changes.
- Location registry: ID, owner, status, template version, creation date, QA date.

## Pipeline checklist

For each pipeline define stage vocabulary, required fields, owner, next action, advancement evidence, blocker/follow-up rules, attribution, revenue fields, and stale-record handling.

## Evidence boundaries

A sent message is not engagement. A reply is not a booked meeting. A booked meeting is not a completed call. A deal is not collected cash. A created asset is not a verified workflow. A plan/inventory must not be reported as implementation.

## Presentation sequence

Outcomes → operating model → architecture → channel/data flow → people/RACI → daily cadence → weekly KPIs → pilot → launch gates → risks/decisions → scale path.

## Backlog pattern

Create P0 discovery/decision tasks for missing access, unclear tool identity, undefined business terms, and unassigned owners before P1 build tasks. Make the presentation itself a tracked deliverable. Keep outbound activation behind consent/suppression, sender authentication, copy approval, QA, and controlled-test gates.
