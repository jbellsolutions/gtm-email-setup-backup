# Browser Evidence and Illustrative Fallback

## Reusable pattern

When a requested story angle calls for a real local-business case but no sufficiently verifiable named case is available:

1. Browser-open an official current affiliate-program or community/networking page.
2. Capture the final URL, exact page title, research date, and verbatim lines used.
3. Separate what the page proves from what it does not prove. For example, program existence and referral mechanics do not prove approval, guaranteed income, attribution duration, or a local-business outcome.
4. Build the story around the verified angle, not an invented result.
5. Use a clearly marked illustrative/composite protagonist only if it helps make the plan concrete.
6. Label the illustrative status in the customer-facing copy and image caption/alt text.
7. Add a source-ledger note explaining that no named case was used and why.

## QA evidence fields

- Source URL and final page title
- Browser success or block result
- Exact supporting quote(s)
- Claims permitted
- Claims intentionally omitted
- Whether the source is official
- Freshness recheck required before send

## Draft gate

If destination, CTA URL, generated images, or opt-in/outbound framing is unresolved, deliver as a draft with a visible placeholder and an explicit blocker list. Do not load or send it.
