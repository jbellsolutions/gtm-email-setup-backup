# Story-Led Newsletter Production

Use this class-level skill for newsletters that sell through one continuous narrative rather than cards, roundups, or numbered offer lists. The reader is the hero; the publication is the guide. This is especially useful when a local-business mission must be carried by a real, current angle without overstating evidence.

## Core workflow

1. Read the publication identity skill and shared pipeline/QA guidance. Preserve the publication's voice, byline, sender metadata, address, merge tags, and distinct design footprint.
2. Choose one real, current angle. Browser-verify the exact page in a real browser, then record the final URL, page title, date, and verbatim evidence in a source ledger.
3. Prefer a named, real local-business case when it can be verified. If no suitable named case is available, use a real official affiliate-program, community, or networking source as the angle carrier. Never invent a business, outcome, commission, quote, or relationship.
4. If an illustrative protagonist or composite scene is needed, label it in customer-facing copy and image alt/caption text. State in the ledger which claims the source supports and which it does not.
5. Draft one StoryBrand arc: hero -> pressure/problem -> guide empathy and authority -> practical plan -> stakes -> one clear mission-framed CTA. Do not use a TOC, editorial cards, offer roundup, or competing CTAs.
6. Write labeled, text-safe image prompts. Keep logos, readable signage, product claims, testimonials, commission figures, and invented statistics out of generated images.
7. Build email-safe HTML with inline CSS, white/spacious layout when required, approved merge tags, physical address, unsubscribe, and view-online links. If destination is unresolved, use a clearly marked draft placeholder only; never imply send-readiness.
8. Produce the source ledger, image-prompt handoff, and QA report. Run checks for prohibited wording/brand leakage, required merge tags, address, inline-CSS constraints, illustrative labeling, and file presence.

## Evidence boundaries

A source establishes only claims visible on the verified page. An affiliate-program page may establish program existence, referral mechanics, links, tracking, or stated commission language, but not guaranteed approval, income, geography, attribution windows, or sponsorship unless explicitly stated. A community organization page can support networking/community framing but does not prove affiliate performance. Keep those boundaries visible in the ledger and copy.

## Draft and approval gates

Destination/platform, CTA URL, opt-in versus outbound framing, generated image assets, and final freshness checks are blockers before send. Draft-only means no platform load, test-send, or send. Report blockers plainly rather than calling the artifact send-ready.

## Pitfalls

- Rebuilding a retired deals roundup because old files still exist. Treat prior roundup HTML and offer ledgers as obsolete unless the current identity explicitly asks for them.
- Presenting an invented local owner as a named case. Use “illustrative” or remove the scene.
- Turning one verified program page into unsupported performance claims.
- Treating a placeholder CTA as a real destination.
- Using a generic narrow newsletter template when the identity calls for a distinct wider look.
